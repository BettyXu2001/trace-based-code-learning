# Execution-aware Code Learning System
## 基于执行语义的代码学习与理解系统

> **项目名称**：trace-based-code-learning

## Why
现有代码学习工具的局限：
- **静态解释工具**（ChatGPT/Copilot）：只看代码，容易产生幻觉（hallucination）
- **Debug工具**：给开发者，不是给学习者

**本质升级**：从"讲代码是什么" → "讲代码是如何运行并产生结果的"

**核心差异点**：
- 现有产品要么只看代码（静态），要么只是debug工具（动态）
- 本系统是：结构理解 + 执行理解统一
- AI驱动的代码**学习系统**，不是给开发者的工具

## 产品定义

**输入**：
- 一个代码仓库 / 单文件代码
- 用户自定义测试输入

**输出**：
- 结构化课程（类似codebase-to-course）
- 执行驱动的动态讲解
- 可运行、可解释、可验证的学习内容

**最终效果**：不只是文档，而是"可运行、可解释、可验证的课程"

## 系统架构（三层）

### 1. 静态分析层
**职责**：讲清楚整体结构

**能力**：
- AST解析
- 代码切分（function-level chunk）
- 模块划分（module / class / function）
- 依赖关系构建（谁调用谁）
- 学习路径生成（从简单到复杂）

### 2. 动态执行层（核心亮点）
**职责**：获取真实执行数据

**能力**：
- trace采集（sys.settrace / AST instrumentation）
- execution timeline构建
- loop压缩 / path抽象
- 分支路径记录
- 异常轨迹捕获

**关键处理**：
- 循环合并（loop summarization）："循环执行10次，变量x从1→10"
- 只保留关键step（关键路径）

### 3. 生成与组织层
**职责**：生成课程内容和执行讲解

**Prompt模板**：
- 结构讲解Prompt：生成模块概述、依赖关系
- 执行解释Prompt：基于trace生成step-by-step解释
- 内容编排Prompt：生成课程结构

**输出内容**：
- 概念讲解（LLM生成）
- 示例代码
- 执行演示（trace驱动）
- 常见错误（可选）

## 核心功能模块

### Module 1: 代码结构解析
生成结构化学习路径

**输出示例**：
```
Lesson 1：基础函数（greet函数）
Lesson 2：核心逻辑（calculate函数）
Lesson 3：复杂流程（主函数）
```

### Module 2: 执行驱动讲解（核心差异）
在每个lesson里引入：
- 真实执行轨迹
- 变量变化过程
- 分支路径选择原因

**对比示例**：

传统讲解（静态）：
> "这个函数用于计算最大值"

Execution-aware讲解（动态）：
> "当输入 [3,1,5] 时：
> 第1步：max=3
> 第2步：比较1，max不变
> 第3步：比较5，max更新为5
> → 最终输出5"

### Module 3: 交互式执行（关键产品能力）
用户可以：
- 自定义输入
- 看到不同执行路径

**示例**：
```
输入 x=3 → 走if分支
输入 x=-1 → 走else分支

系统自动输出：
- 路径差异
- 关键变量变化
```

这一步让产品从"内容"变成"工具"

### Module 4: 自动课程生成
每个课程单元包含：
- 概念讲解
- 示例代码
- 执行过程（step-by-step）
- 输入变化对比

## 高阶增强功能（拉开差距）

### Enhancement 1: 错误注入（Error Injection）
**目标**：自动生成错误案例 + 解释错误原因

**能力**：
- 识别代码中的潜在错误点（除零、越界、空指针等）
- 生成"错误输入"触发这些错误
- 解释为什么错误发生

**示例**：
```
原始代码：list[10] when list has only 5 elements
系统自动生成：
- 输入：[1,2,3,4,5]
- 触发错误：IndexError at line 10
- 解释：尝试访问索引10，但列表长度只有5
```

### Enhancement 2: 路径对比（Path Diff）
**目标**：不同输入 → 执行路径差异分析

**能力**：
- 用户提供多个输入
- 系统分析并对比执行路径
- 标红显示路径分叉点

**示例**：
```
输入 A: x=5 → 路径：1→2→3→5→end
输入 B: x=-1 → 路径：1→2→4→end

差异点：
- Step 3: x=5时进入if分支，x=-1时进入else分支
- 原因：x>0 条件判断
```

### Enhancement 3: 知识抽象（Concept Extraction）
**目标**：从执行中总结"算法思想"（而不是只讲代码）

**能力**：
- 分析执行模式
- 提取算法策略（如：分治、贪心、动态规划）
- 生成高层次的算法思想讲解

**示例**：
```
代码：快速排序实现
知识抽象输出：
"本代码采用分治策略：
1. 选择基准元素（pivot）
2. 将小于基准的元素移到左侧，大于的移到右侧
3. 递归处理左右两部分
这体现了'分而治之'的算法思想"
```

## ADDED Requirements

### Requirement: 代码结构解析
系统 SHALL能够解析代码仓库/文件并生成学习路径。

#### Scenario: 单文件分析
- **GIVEN** 用户输入单文件Python代码
- **WHEN** 系统分析代码结构
- **THEN** 识别函数、类、模块依赖，生成学习路径

#### Scenario: 代码切分
- **GIVEN** 复杂函数（100+行）
- **WHEN** 系统分析
- **THEN** 按功能块切分为可理解的单元

### Requirement: 执行轨迹采集
系统 SHALL能够在运行时采集代码的执行轨迹。

#### Scenario: 基础轨迹采集
- **GIVEN** 用户输入Python代码和测试输入
- **WHEN** 系统执行代码
- **THEN** 返回结构化轨迹，包含行号、变量状态、调用栈

#### Scenario: 分支路径记录
- **GIVEN** 代码包含if/else分支
- **WHEN** 执行时选择了特定分支
- **THEN** 轨迹标注哪个分支被执行及条件判断结果

#### Scenario: 循环轨迹压缩
- **GIVEN** 代码包含循环执行100次
- **WHEN** 系统采集轨迹
- **THEN** 轨迹压缩为"循环执行100次，变量i从0→99"

#### Scenario: 异常轨迹捕获
- **GIVEN** 代码执行时抛出异常
- **WHEN** 系统采集轨迹
- **THEN** 返回完整的异常信息和调用栈

### Requirement: 执行驱动讲解生成
系统 SHALL能够基于轨迹生成带有执行证据的讲解。

#### Scenario: Step-by-step讲解
- **GIVEN** 执行轨迹
- **WHEN** 生成讲解
- **THEN** 每个讲解步骤引用对应的trace step（citation）

#### Scenario: 变量变化讲解
- **GIVEN** 变量值发生变化
- **WHEN** 生成讲解
- **THEN** 说明变量变化的原因和结果

#### Scenario: 分支选择讲解
- **GIVEN** 进入某个分支
- **WHEN** 生成讲解
- **THEN** 说明"因为X条件成立，执行此分支"

### Requirement: 交互式执行
系统 SHALL支持用户自定义输入并观察不同执行路径。

#### Scenario: 自定义输入执行
- **GIVEN** 用户修改输入参数
- **WHEN** 系统重新执行
- **THEN** 显示新的执行轨迹和路径差异

### Requirement: 课程生成
系统 SHALL能够生成完整的结构化课程。

#### Scenario: 单文件课程生成
- **GIVEN** 用户输入一个完整的Python文件
- **WHEN** 系统分析并生成课程
- **THEN** 输出多lesson的课程，包含结构讲解和执行演示

#### Scenario: 学习路径
- **GIVEN** 代码包含多个函数/类
- **WHEN** 生成课程
- **THEN** 按依赖关系排序，从简单到复杂

### Requirement: 可视化展示
系统 SHALL提供直观的可视化界面。

#### Scenario: 执行时间轴
- **GIVEN** 已完成代码分析
- **WHEN** 用户查看
- **THEN** 显示step 1 → step n的执行流程

#### Scenario: 变量状态面板
- **GIVEN** 执行到某一步
- **WHEN** 显示变量状态
- **THEN** 展示所有当前变量的值

#### Scenario: 课程结构导航
- **GIVEN** 已生成课程
- **WHEN** 用户浏览
- **THEN** 可在lesson间切换，查看每个lesson的讲解和执行演示

### Requirement: 错误注入（扩展）
系统 SHALL能够自动生成错误案例并解释错误原因。

#### Scenario: 错误点识别
- **GIVEN** 用户代码存在潜在错误
- **WHEN** 系统分析
- **THEN** 识别错误类型（除零、越界等）并生成错误输入

#### Scenario: 错误解释
- **GIVEN** 触发了一个错误
- **WHEN** 生成解释
- **THEN** 说明错误原因和修复方向

### Requirement: 路径对比（扩展）
系统 SHALL能够对比不同输入的执行路径差异。

#### Scenario: 路径差异分析
- **GIVEN** 用户提供多个输入
- **WHEN** 系统执行并分析
- **THEN** 高亮显示路径分叉点

### Requirement: 知识抽象（扩展）
系统 SHALL能够从执行中提取算法思想。

#### Scenario: 算法思想提取
- **GIVEN** 用户代码实现了某种算法
- **WHEN** 系统分析执行模式
- **THEN** 输出高层次的算法思想讲解

## 关键创新点（面试重点）

### 1. 静态 + 动态结合
- 现有产品：要么只看代码（静态），要么只是debug工具（动态）
- 本系统：结构理解 + 执行理解统一

### 2. 从"解释代码"到"解释执行过程"
- 静态解释 → 容易错（hallucination）
- 动态解释 → 有ground truth

### 3. 从"工具"到"学习系统"
- debugger：给开发者
- 课程生成：给学习者
- 本系统：AI驱动的代码学习系统

### 4. 执行驱动的错误理解
- 自动注入错误 → 理解为什么出错
- 路径对比 → 理解条件分支含义
- 知识抽象 → 理解算法本质
